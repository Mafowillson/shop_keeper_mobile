# ShopKeeper Flutter App - Setup Guide

## Project Overview

ShopKeeper is a complete Flutter mobile application for inventory management with 111 source files, 8,000+ lines of code, implementing Clean Architecture with Provider state management, functional programming, and comprehensive dependency injection.

## System Requirements

Before getting started, ensure you have the following installed:

- Flutter 3.24.0 or higher
- Dart 3.5 or higher
- Android SDK 26+ (for Android development)
- iOS 14+ (for iOS development)
- Git for version control

## Installation Steps

### Step 1: Clone or Extract the Project

If you have the project as a compressed file, extract it to your desired location:

```bash
cd ~/projects
unzip shopkeeper_flutter.zip
cd shopkeeper_flutter
```

### Step 2: Get Flutter Dependencies

Install all required Flutter packages:

```bash
flutter pub get
```

This will download and install all dependencies specified in pubspec.yaml, including provider, go_router, fpdart, get_it, injectable, and other packages.

### Step 3: Generate Dependency Injection Code

The project uses injectable for automatic DI code generation. Run the build_runner to generate the injection.config.dart file:

```bash
dart run build_runner build --delete-conflicting-outputs
```

This command will:
- Scan all @injectable and @lazySingleton annotations
- Generate the dependency injection configuration
- Create the injection.config.dart file automatically

### Step 4: Verify Installation

Check that everything is set up correctly:

```bash
flutter doctor
flutter analyze
```

The analyze command should complete without errors (warnings are acceptable).

## Project Structure

The project follows Clean Architecture with three distinct layers:

**Core Layer** contains shared utilities, themes, constants, and reusable widgets.

**Domain Layer** contains business logic, entities, repository interfaces, and use cases.

**Data Layer** implements repositories and manages data sources (currently using mock data).

**Presentation Layer** contains screens, providers for state management, and UI components.

Each feature (Auth, Dashboard, Products, Sales, Debts, Notifications, AI Chat, Staff) has its own complete domain-data-presentation structure.

## Development Workflow

### Adding a New Feature

1. Create domain layer files (entities, repositories, use cases)
2. Create data layer files (models, datasources, repository implementations)
3. Create presentation layer files (providers, screens, widgets)
4. Update DI configuration in injection.dart
5. Add routes to app_router.dart

### Modifying Existing Features

1. Update the entity or use case in the domain layer
2. Update the model and datasource in the data layer
3. Update the provider in the presentation layer
4. Regenerate DI code if you added new injectable classes

### Connecting to Backend

To connect to the Golang backend:

1. Replace mock datasources with real implementations
2. Implement HTTP calls using the ApiClient
3. Update models to match API responses
4. No changes needed to providers, use cases, or screens

## Code Generation

Several files are auto-generated and should not be manually edited:

- `lib/di/injection.config.dart` - Generated by injectable
- Any files marked with `// GENERATED CODE`

To regenerate these files:

```bash
dart run build_runner build --delete-conflicting-outputs
```

To watch for changes and regenerate automatically:

```bash
dart run build_runner watch
```

## Troubleshooting

### Issue: Build Runner Fails

**Solution:** Clean and rebuild:
```bash
flutter clean
flutter pub get
dart run build_runner build --delete-conflicting-outputs
```

### Issue: Dependency Conflicts

**Solution:** Update dependencies:
```bash
flutter pub upgrade
dart run build_runner build --delete-conflicting-outputs
```

### Issue: App Crashes on Startup

**Solution:** Check that all providers are registered in app.dart and that the DI configuration is generated.

### Issue: Navigation Not Working

**Solution:** Verify that all routes are defined in app_router.dart and that the GoRouter is properly configured in app.dart.
